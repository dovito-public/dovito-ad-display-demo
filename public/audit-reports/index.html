A worked example of our codebase audit methodology, applied to a public demo repository. Every finding is reproducible — just clone the repo and check.

What this is

A real audit on a public codebase

Most of our client audits produce a report the client never shares. We wanted a version we could share — same structure, same methodology, same rigor — so prospects can read exactly what they will get when they hire us. The subject is a static, frontend-only fork of our Dovito Ad Display product, published as an open repository at dovito-public/dovito-ad-display-demo.

Because the demo has been intentionally reduced to a single-page app backed by localStorage, some audit categories (multi-tenancy, billing, monitoring) score near zero. Rather than hide that, we wrote the report to make the gap analysis itself the deliverable. That framing is the point of this case study: even when the answer is "not yet," a structured assessment tells you exactly what to build and in what order.

Methodology

The eight phases

Every Dovito codebase audit follows the same eight-phase process, whether the subject is this demo or a six-figure client engagement.

  • Baseline metrics — LOC, file count, dependency graph, routes, endpoints, tests, commit SHA
  • Architecture review — layering, abstractions, coupling, separation of concerns
  • Code quality review — type safety, error handling, consistency, documentation, DX, letter grades across nine dimensions
  • Security review — findings numbered SEC-NNN, categorised by severity (Critical / High / Medium / Low / Info), each with file:line and remediation
  • Performance assessment — bundle, rendering, assets, network, runtime — directional scoring with cited evidence
  • SaaS readiness — 7-dimension rubric, component-level gap analysis, implementation order
  • Cost analysis — replacement value at three rate tiers, team cost with overhead multipliers, calendar time
  • Recommendations & roadmap — phased, priced, dependency-ordered plan
